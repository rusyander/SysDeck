# Тесты Windows Process Cleaner

[← Обзор](../README.md) · [Все разделы руководства](README.md)

Набор проверок, который держит в узде самое дорогое в этом приложении — решение «этот файл
можно удалить». Ставить ничего не нужно: как и сама программа, тесты компилируются встроенным
в Windows `csc.exe` из .NET Framework 4.x.

## Как запустить

```
tests\run-tests.bat
```

Скрипт собирает `src\*.cs` вместе с `tests\*.cs` во временную папку (`%TEMP%\wpc-test-build`)
и запускает результат. Файл `WindowsProcessCleaner.exe` в корне репозитория при этом не
трогается. Каждая проверка печатает одну строку:

```
PASS a masked target does not recurse unless asked
FAIL a file older than the fresh-files window is deleted  [expected <100>, got <0>]
SKIP the Windows.old leftover keeps the ten-day rollback window  [no C:\Windows.old]
RESULT 348 passed, 0 failed, 8 skipped
```

Код возврата равен числу упавших проверок, поэтому `run-tests.bat` годится и для автоматики.
`SKIP` — это проверка, для которой на ЭТОЙ машине нет данных (папки программы, которая здесь не
установлена). Она не засчитывается ни в успех, ни в провал: зелёный прогон нигде не выдаёт
непроверенное за проверенное.

## Изоляция данных

Программа хранит настройки, историю и логи в `%APPDATA%\WindowsProcessCleaner`. Тесты подменяют
эту папку переменной `WPC_DATA_DIR` и убеждаются в подмене ещё до создания движка: если подмена
не сработала, прогон прекращается сразу, не начавшись. Настоящий `config.json` пользователя
сверяется по времени изменения в конце прогона.

Все проверки, которые действительно удаляют файлы, работают внутри одной временной папки под
`%LOCALAPPDATA%\Temp` и через категорию, собранную руками, с выключенной Корзиной; попытка
запустить удаление с целью вне этой папки роняет прогон. Дерево фикстур удаляется в конце.

Цепочка целиком (`Tests.MediaIntegration.cs`): поток HLS проходит очередью через настоящую склейку в файл, который читает Media Foundation (все кадры на месте), папка частей исчезает после успеха и удаляется вместе с загрузкой, настройка качества доходит до выбора варианта, строка списка показывает куски и записанное время |
| `Tests.Browsers.cs` | обратная запись закладок: копия настоящего профиля и собранный вручную файл переписываются производственным кодом, контрольная сумма пересчитывается, временный файл не остаётся |

## Что сознательно не покрыто

- **Окно**: разметка, темы, цвета, поведение вкладок. Проверяется снимками экрана, а не тестами.
- **Полка выбора на уровне окна** (`MainForm.Memory.cs`): вытеснение по времени последнего
  касания живёт внутри формы и требует поднять весь интерфейс. Проверен слой конфига — потолок,
  порядок вытеснения и кодировка записей.
- **Всё, что требует запроса прав администратора или запуска системной утилиты**: `schtasks`,
  `pnputil`, DISM, SFC, точка восстановления, взятие владения файлом TrustedInstaller, сбросы
  памяти на вкладке «Память». Задача автозапуска проверяется как текст; настоящая задача
  планировщика не создаётся, не изменяется и не удаляется. Ни один тест не сбрасывает память
  машины: проверяется ровно обратное — что команда вне белого списка отвергается.
- **«Размеры папок» в Проводнике**: наложение чисел, панель и трей проверяются вживую; настоящий
  `$MFT` не читается (нужны права), задача Планировщика не создаётся, автозапуск не трогается,
  событиям работающего фонового режима тест не сигналит. Консольная проверка пропускается, если
  exe старее `src\FolderSize.Tray.cs`.
- **Сеть**: загрузка базы правил winapp2, проверка ссылок, опрос winget и Chocolatey.
- **Загрузки вне локального сервера**: HTTPS (локальный HTTPS-сервер без прав администратора не
  поднять — переход https → http проверяется на функции разбора редиректа), сканирование Defender,
  запрет сна, настоящие лимитная сеть, батарея и простой ПК (подменяются), значение автозапуска в
  `HKCU\...\Run` (тест его не пишет), сам фоновый процесс `--downloads` (канал поднимается внутри
  прогона). Докачка настоящего файла по HTTPS после убитого процесса проверяется вживую, как и сама
  вкладка «Загрузки» (окно, диалоги, уведомление, уход процесса через минуту). Настоящий rutracker —
  его API и перезалитая раздача — в набор не входит: проверка идёт против поддельного API на петле.
- **Настоящие браузеры**: хост проверяется запуском так, как его запускают браузеры, но само расширение в браузере
  набор не поднимает (у расширения свои тесты на Node в `extension\test\`). Перехват в Edge и Firefox с настоящими
  ключами реестра проверяется вживую; ключи после проверки удаляются. Удаление ключей деинсталлятором — тоже вживую,
  под тестовым ключом.
- **Корзина**: ни одна проверка не включает её и не очищает.
- **Docker, обновления, программы, автозапуск в реестре**: их поведение завязано на состояние
  машины и проверяется вживую, а не набором.
