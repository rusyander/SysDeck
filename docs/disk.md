# Диск: очистка, карта места, размеры папок и Docker

Разделы «Очистка диска», «Диск» и Docker: что считается мусором, как устроен предпросмотр и удаление, чем занято место и как его вернуть.

## Очистка диска (только вручную)
Отдельная вкладка. Флоу: **Анализировать → предпросмотр с размерами → удалить
выбранное**. Автоочистки диска нет намеренно (файлы менее обратимы, чем процессы).
Чистятся только **известные мусорные пути**; карта диска, крупные файлы, пустые папки и
дубликаты живут на соседней вкладке «Диск». Категории:
- **Dev-кэши** — npm / pnpm / yarn / bun / pip / uv / poetry / gradle / cargo / go / NuGet /
  Composer / TypeScript (всё пересоздаётся). У cargo убирается только распакованное
  (`registry\src`), а скачанные архивы `registry\cache` остаются: из них всё разворачивается
  заново без сети, и `cargo build --offline` продолжает работать.
- **Dev: скачанные тулчейны** — старые сборки браузеров Playwright (текущая остаётся; проект,
  закреплённый на прошлой версии, после удаления потребует `npx playwright install`), браузеры
  Puppeteer/Cypress, electron-builder, dotslash, Expo Go, репозиторий Maven, пакеты NuGet
  (`~/.nuget/packages`). Скачаются заново, но долго — тихая `/auto` их не берёт.
- **Системный мусор** — `%TEMP%`, `Windows\Temp`, temp служебных профилей, Корзина, кэш
  Windows Update, crash dumps, отчёты об ошибках, Delivery Optimization. `Prefetch` намеренно
  не трогается: это кэш запуска программ, весит мегабайты, а после удаления всё стартует
  медленнее, пока Windows не соберёт его заново.
- **Кэши Windows** — thumbcache/iconcache, кэш шрифтов, картинки уведомлений, кэш RDP —
  Windows пересобирает их сама.
- **Кэши шейдеров GPU** — DirectX (`D3DSCache`), NVIDIA/AMD/Intel и `shadercache` Steam.
  После очистки игры и Chrome/Electron компилируют шейдеры заново и первые минуты
  подтормаживают, а места это даёт мало — тихая `/auto` их не берёт.
- **Кэши приложений Microsoft Store** — `INetCache` / `Temp` / `TempState` каждого UWP-пакета
  и WebView-кэш нового Teams. `LocalState` и настройки приложений не трогаются.
- **Кэши браузеров** — Chrome / Edge / Brave / Yandex / Opera / Vivaldi / Firefox, только кэш
  (без паролей, куки и истории).
- **Кэши приложений** — Discord / Slack / Teams / Spotify (встроенный браузер) / VS Code /
  JetBrains / Steam / Telegram (включая `media_cache`) / Figma / игровые лаунчеры, только кэш.
- **Кэши с офлайн-контентом** — Spotify `Storage`/`Data`: потоковый кэш вместе с офлайн-загрузками
  Premium. Треки скачаются заново, поэтому категория не отмечена по умолчанию.
- **NVIDIA: кэши и старые версии** — старые версии моделей NGX (DLSS, Broadcast и т.д.).
  NGX Updater докачивает новые версии в `ProgramData\NVIDIA\NGX\models\<модель>\versions`
  и никогда не удаляет старые — за год набегают гигабайты. Плюс кэш NVIDIA App/Overlay,
  загрузчик драйверов, `C:\NVIDIA`. Самая новая версия каждой модели и сам драйвер остаются.
  База распознавания игр NVIDIA App (`NvBackend\ApplicationOntology`) не трогается: без неё
  NVIDIA App перестаёт узнавать игры, пока не скачает базу заново.
- **Старые логи** — логи CBS/DISM/установки Windows, Update Orchestrator, npm/yarn/gradle,
  Docker Desktop, OneDrive, Zoom, Chocolatey.
- **Списки недавних файлов** — «Недавние документы», списки переходов (приватность).
- **Старые версии программ** — копии предыдущих версий, которые оставляют автообновления:
  Squirrel-приложения (Postman, Figma, Discord и т.п. держат папку `app-<версия>` на каждую
  скачанную версию) и WPS Office (папка предыдущей версии рядом с текущей). Текущая версия
  определяется по номеру, у WPS — по реестру. Не отмечается по умолчанию.
- **Остатки обновлений Windows и драйверов** — `Windows.old`, `$Windows.~BT`, `$WinREAgent`,
  `$GetCurrent`, `$SysReset` (следы прошлого сброса системы), `ESD`, распакованные установщики
  AMD/Intel, загрузчик NVIDIA. Не трогаются `NVIDIA Installer2` и кэш MSI-патчей
  `Windows\Installer\$PatchCache$`: из них система чинит и удаляет уже установленное, а без них
  восстановление патчей Office, SQL Server и Visual Studio просит исходный установщик, которого
  у пользователя обычно уже нет. Всё в этой категории удаляется только старше 10 дней — столько
  их хранит сама Windows на случай отката, и столько же идёт установка драйвера.
- **Старые пакеты драйверов (DriverStore)** — версии, которые заменены более новыми и не
  привязаны ни к одному устройству. Список строится по `pnputil /enum-drivers`, удаление —
  `pnputil /delete-driver` без `/force`: если пакет нужен системе, pnputil откажет сам.
  Папки в `FileRepository` напрямую не удаляются никогда.
- **Хранилище компонентов Windows (WinSxS)** — устаревшие версии компонентов, оставшиеся
  после обновлений. Размер считается `DISM /AnalyzeComponentStore`, очистка —
  `DISM /StartComponentCleanup` (единственный поддерживаемый способ). После неё уже
  заменённые обновления нельзя откатить, поэтому тихая `/auto` её не берёт.

Галочки в окне при первом анализе: отмечены «Старые логи», «Остатки обновлений Windows и
драйверов», «Кэши шейдеров GPU», «Dev: скачанные тулчейны» и «Хранилище компонентов Windows (WinSxS)», не отмечены «Кэши Windows» и «NVIDIA: кэши и старые версии». Поставленные вручную
галочки окно запоминает. Тихая очистка `/auto` берёт запомненные галочки, а для категорий,
которых в окне не касались, — свой набор: кэши Windows и NVIDIA чистит, логи и остатки
обновлений — нет.

Предохранители: пропускаются занятые файлы и точки повторного разбора (junction); напрямую
никогда не трогаются `DriverStore` (только через `pnputil`), `Windows\Installer`, WinSxS,
System32, корни дисков, код и проекты. Файлы, которые изменялись в последние N минут, не
удаляются (N настраивается, по умолчанию 10). Категории с несколькими версиями одной
сущности всегда оставляют самую новую. Каждая очистка пишется в лог `clean-ГГГГ-ММ.log` —
кнопка «Лог» открывает его.

**В `%ProgramData%` и `Program Files` очистка разрешительная, а не запретительная.** Там
программа держит не только кэш, но и собственный дистрибутив — архивы, из которых она
доставляет и чинит свои компоненты. По имени папки их не отличить: у Logitech G HUB склад
установщика называется `cache`, у NVIDIA — `Installer2` и `Downloader`, у Wargaming и
Battle.net — снова `cache`. Правило, написанное по имени, уносит вместе с кэшем возможность
программы починиться: она продолжает запускаться и начинает жаловаться на отсутствующие файлы.
Поэтому в этих деревьях удаляется только то, что одноразово по своей природе — журналы
(`.log`, `.etl`, `.trace`), дампы (`.dmp`), временные файлы, а также всё содержимое папок
`Logs`, `Temp`, `CrashDumps`, `WER`, — и ничего больше, даже если правило просит папку
целиком. Исключение делается поштучно и только там, где проверено, что приложение восстановит
содержимое само (старые версии моделей NGX у NVIDIA). Отдельно и на любой глубине закрыты
`Package Cache`, `$PatchCache$`, `Installer2` и склад Logitech: из них Windows и драйверы
чинят и удаляют уже установленное.

**Состав категории.** Двойной клик по категории (кнопка «Состав…» или Enter) открывает
список её папок: путь, размер, число файлов и примечание — только содержимое или папка
целиком, фильтр по возрасту, сколько папок оказались недоступны. Самое крупное сверху.
Снимите галочку с того, что удалять не нужно, — выбор запоминается в `config.json` и
действует при каждом анализе и удалении, пока вы не вернёте галочку. Отключённые папки не
входят в размер категории, а в её описании появляется пометка «отключено вами: N». Пакеты
драйверов исключаются так же, по одному; у хранилища компонентов (DISM) состава нет.
Двойной клик по строке или «Открыть папку» показывает её в проводнике.

**Правила winapp2 (необязательно).** Кнопка «Правила winapp2» скачивает
[Winapp2.ini](https://github.com/MoscaDotTo/Winapp2) — открытую базу с тысячами правил
очистки для конкретных программ, и добавляет их к встроенным категориям. Из неё берутся
**только правила удаления файлов**: разделы с предупреждениями (`Warning=`) и с
исключениями (`ExcludeKey`) пропускаются целиком, а правила для реестра игнорируются —
реестр программа не чистит вообще. Результаты из winapp2 никогда не отмечаются галочкой
автоматически.

Файл правил — это чужой текст, который приложение исполняет правами администратора, поэтому
он ограничен отдельно от встроенных правил:

- **Скачанная база лежит в защищённой папке** `C:\ProgramData\SysDeck\` с
  правами «администраторы и SYSTEM — полный доступ, пользователи — только чтение». В прежнем
  месте (`%APPDATA%`) файл мог переписать любой процесс, запущенный от вашего имени, — а
  чистка идёт от администратора. Старая копия при следующей загрузке удаляется. Если папку
  создать не удалось (запуск без прав администратора), используется прежнее место.
- **Правилу из файла закрыты системные пути целиком**: внутрь `C:\Windows` оно попадает
  только в заведомо мусорные подпапки (`Temp`, `Prefetch`, `Logs`, `Minidump`, `Debug`,
  `SoftwareDistribution\Download`, `System32\LogFiles`, `Downloaded Program Files`), в
  `Program Files` и в чужие профили пользователей — никогда, и корень `C:\Windows` не
  открывается даже узкой маской вида `%WinDir%|*.log`. Встроенные правила (MEMORY.DMP в
  `C:\Windows`, `IconCache.db` в `%LOCALAPPDATA%`) работают как прежде: их нельзя подменить.
- **Предохранитель сохранений и служебных баз действует на каждую папку обхода**, а не
  только на корень правила: правило с `RECURSE` над `%LocalAppData%\NVIDIA Corporation`
  не спустится в `NvBackend\ApplicationOntology`, а над профилем — в `Saved Games`.

## Диск
Отдельная вкладка: **где место и что можно убрать руками**. Выбираете диск или папку
(«Где искать»), нажимаете **Сканировать** — слева дерево папок с размером, долей от
родительской папки и числом файлов (раскрывается по мере надобности), справа список в одном
из трёх режимов:
- **Крупные файлы** — файлы не меньше порога «Файлы от N МБ» (по умолчанию 1 МБ, значение
  запоминается) в выбранной папке и её подпапках, по убыванию размера. Порог можно поднять и
  после сканирования — список сузится сразу; опустить ниже того, с которым шёл обход, —
  только пересканировав (программа подскажет).
- **Пустые папки** — только верхние пустые: если пуста `a\b\c`, показана `a`, а сколько
  вложенных пустых внутри — в строке над списком.
- **Дубликаты** — файлы не меньше того же порога с одинаковым содержимым. Сравнение идёт в три шага: размер →
  первые 64 КБ → полный SHA-256, поэтому целиком читаются только настоящие кандидаты.
  В группе первым идёт самый старый файл (обычно оригинал); кнопка **Все** отмечает в каждой
  группе все копии, кроме него.

Удаление — только **В Корзину**, одной операцией оболочки и после подтверждения; всё
восстанавливается штатно из Корзины. По умолчанию ничего не отмечено. Двойной щелчок по
папке или **Открыть папку** показывает её в Проводнике.

Что учтено:
- Внутри `Windows`, `Program Files`, `ProgramData`, `AppData\Local\Packages`, `node_modules`
  и `.git` пустые папки и дубликаты не предлагаются — там одинаковые файлы и пустые каталоги
  в порядке вещей, а удаление ломает программы.
- Точки повторного разбора (junction, symlink, папки OneDrive) не раскрываются и не
  считаются дважды; у папки в дереве видно, сколько ссылок пропущено и куда нет доступа.
  Пути длиннее 260 знаков читаются, хэшируются и переносятся в Корзину (оболочке они
  передаются короткими именами 8.3; на томе, где короткие имена отключены, такой путь
  в Корзину не попадёт — программа скажет, сколько путей осталось).
- Скрытые и системные файлы в дубликаты не попадают.
- Полосы занятости всех дисков — над деревом. Скан не отменяется при переходе на другую
  вкладку; **Стоп** прерывает его.
- Ключ `/disk [путь]` открывает вкладку и сразу сканирует путь — удобно для ярлыка или
  вызова из Проводника.

## Размеры папок
Проводник в колонке «Размер» у папок оставляет пусто. Эта вкладка управляет **фоновым режимом**,
который дописывает туда точный размер каждой папки поверх окна Проводника и ставит рядом
боковую панель: папки текущего окна по убыванию размера, с полосой доли и числом файлов.

Числа берутся из активной вкладки Проводника и только для той папки, что в ней открыта: при переключении вкладок
или переходе в другую папку прежние числа сразу снимаются. Во время прокрутки колесом числа прячутся и
возвращаются, когда список остановился, — вместо того чтобы догонять строки.

- **Отдельный процесс.** Фоновый режим — тот же exe с ключом `--foldersize`, со своим значком
  в трее. Он не зависит от окна программы: окно закрыто — числа в Проводнике остаются.
  Щелчок по значку показывает и прячет панель, правый щелчок — меню со всеми настройками.
- **Вкладка:** «Запустить», «Остановить», «Показать панель», состояние (запущен ли и с правами
  ли), те же настройки, что в меню трея: числа в Проводнике, перекрытие размеров файлов, панель
  и её сторона, показ только в фокусе или пока окно открыто, индикатор подсчёта, скрытые и
  системные файлы, сдвиг окна Проводника под панель, сортировка, тема. Изменение применяется
  сразу, в том числе в уже работающем фоновом режиме.
- **Быстрые действия** (каждое выключается там же, в настройках, и в меню трея):
  - **Ctrl+Alt+S** показывает и прячет панель из любой программы. Если сочетание уже занято
    другой программой, при включении пункта в меню трея всплывает уведомление, а фоновый режим
    работает без сочетания.
  - **Свободное место** внизу панели: «Диск C: — свободно 120 ГБ из 1,82 ТБ» и полоска занятого,
    красная, когда свободно меньше десятой части. Для сетевой папки — место на её ресурсе.
  - **Меню строки панели:** «Открыть в карте диска» — окно программы открывает вкладку «Диск» и
    сканирует эту папку (уже открытое окно не дублируется); «Копировать список» — вся таблица
    текущей папки через табуляцию (имя, размер, точные байты, файлы, папки и строка «Итого»):
    вставляется в Excel столбцами. У папок, которые ещё считаются, ячейки пустые, а не ноль.
- **Как считается:** папка = сумма настоящих размеров всех файлов внутри, без оценок. Точки
  соединения и символьные ссылки не раскрываются (в ячейке — стрелка): их байты принадлежат
  тому, на что они указывают. В папки, чьё имя Windows переписывает (хвостовая точка или
  пробел, `NUL`, `CON`, `COM1`…), обход не заходит — иначе он пошёл бы по кругу; размер
  родителя тогда помечен «≥». Где нет доступа, число тоже со знаком «≥».
- **Память между запусками.** Посчитанные размеры хранятся до 30 дней (`sizes.json`) и видны
  сразу, пока идёт свежий подсчёт. Папка на экране пересчитывается, когда в ней что-то меняется.
- **Быстрый режим.** С правами администратора таблица файлов NTFS (`$MFT`) читается напрямую —
  весь том за секунды; файл с жёсткими ссылками (например, `node_modules` pnpm) считается в каждой
  папке, где у него есть имя, как в свойствах Проводника. Без прав — обычный обход: числа те
  же, но дольше. Кнопка «Включить быстрый режим» — одно окно UAC: создаётся задача Планировщика
  `SysDeck FolderSize` с наивысшими правами, и фоновый режим перезапускается через
  неё. Дальше он стартует с правами при входе в Windows без UAC, и «Перезапустить с правами
  администратора» в меню трея тоже идёт через задачу.
- **Запуск вместе с Windows:** не запускать, запускать без прав (ключ `Run` в реестре) или
  запускать с правами (та же задача Планировщика). Создать и удалить задачу можно только с
  правами — поэтому переключение на неё и с неё спрашивает UAC.
- **Отдельная программа FolderSizePanel.** Если она запущена или стоит в автозапуске, вкладка
  предупреждает — вдвоём числа в Проводнике рисуются дважды — и предлагает кнопкой остановить
  её и убрать из автозапуска. Сама программа и её файлы остаются на диске. При первом запуске
  фонового режима её настройки и запомненные размеры копируются, если своих ещё нет.
- **Консольные ключи** — в [технических деталях](internals.md).

## Docker
Вкладка для очистки Docker (нужен Docker CLI + запущенный демон). Кнопки: обзор
занятого места (`docker system df`), удалить остановленные контейнеры, неиспользуемые
образы, неиспользуемые тома, очистить кэш сборки, полная очистка всего неиспользуемого.
Удаляется только **неиспользуемое** (`prune`) — запущенные контейнеры и используемые
образы не трогаются.

> ⚠️ **Важно про место на диске.** Docker Desktop хранит всё в одном растущем
> виртуальном диске WSL2 (`docker_data.vhdx`). `prune` освобождает место **внутри**
> этого диска, но сам файл на Windows **не уменьшается**. Чтобы реально вернуть место
> на диске Windows — кнопка **«Сжать диск Docker»**: она останавливает Docker
> (`wsl --shutdown`) и сжимает vhdx через `diskpart compact vdisk`, показывая размер
> до/после. Все запущенные контейнеры при этом завершаются.

Что удалить перед сжатием, задаёт список рядом с кнопкой: «ничего», «безопасное»
(остановленные контейнеры, образы без тега, кэш сборки — по умолчанию), «+ все
неиспользуемые образы» или «всё неиспользуемое, включая тома». Последний вариант стирает
данные баз и других контейнеров в томах, о чём программа предупреждает отдельно.

Kubernetes не включён (его очистка бьёт по живому кластеру).
