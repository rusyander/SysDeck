# win-key-watch

Ловит «залипший» модификатор — состояние, когда система считает клавишу зажатой,
хотя ты её отпустил. Следит за всеми восемью: `LSHIFT RSHIFT LCTRL RCTRL LALT RALT
LWIN RWIN`. Снимает залипание автоматически и попутно собирает улики: кто виноват.

## Как это выглядит со стороны

Залипает каждый раз разная клавиша, поэтому и симптомы разные:

| Залипло | Что видит пользователь |
|---|---|
| `LWIN` | любая буква срабатывает как горячая клавиша: Win+D сворачивает всё, Win+E открывает проводник, Win+G запускает Game Bar |
| `LSHIFT` | колесо мыши прокручивает вбок или «не работает», клик растягивает выделение |
| `LALT` | срабатывают меню и Alt-сочетания |
| `LSHIFT`+`LALT` | плюс постоянно переключается раскладка (это системный хоткей смены языка) |

Зафиксировано: `LWIN` — 05.09 и 06.09, `LSHIFT`+`LALT` — 09.09.

## Как работает

Ставит низкоуровневый хук клавиатуры (`WH_KEYBOARD_LL`) и строит **свою** модель
состояния клавиш — только из событий, реально прошедших через хук. Раз в полсекунды
сравнивает её с тем, что думает система (`GetAsyncKeyState`).

Расхождение = залипание. Срабатывает одно из двух правил, и то, **какое именно**, и
есть ответ на вопрос «кто виноват»:

| Правило | Что произошло | Что это значит |
|---|---|---|
| `RULE-A` | хук увидел отпускание, система его не увидела | отпускание сожрал хук, стоящий **позади** нашего в цепочке — другой перехватчик (оверлей, диктовка, макро-софт) |
| `RULE-B` | отпускание вообще не дошло до нас, а печать продолжалась | событие не родилось или его съели **раньше** нас — инжект без пары либо драйвер/виртуальное устройство |

Каждое нажатие и отпускание модификатора пишется в лог с флагом `injected`:

```
[2026-09-09 13:15:04.252] LCTRL  DOWN injected=0 lowIL=0 scan=29 extra=0x0
[2026-09-09 13:15:02.404] *** LATCH RULE-B: LSHIFT stuck (held 3109ms ...) -> injecting KEYUP
```

* `injected=0` — пришло с физической клавиатуры.
* `injected=1` — клавишу **синтезировал софт** (`SendInput`/`keybd_event`);
  поле `extra` часто содержит подпись приложения-инжектора.

Чтобы правило A не слепло, хук раз в 10 минут переустанавливается — так он остаётся
первым в цепочке, даже если какое-то приложение стартовало позже.

## Файлы

| Файл | Назначение |
|---|---|
| `win-key-watch.ps1` | сам вотчер |
| `unstick-modifiers.ps1` | ручной сброс: показать зажатые и снять (`-WhatIf` — только показать) |
| `install-shortcut.ps1` | ставит на рабочий стол ярлык «Починить клавиши» (`-Uninstall` — убрать) |
| `start-hidden.vbs` | запуск без мелькающего окна консоли |
| `winkey.log` | лог событий и сработавших залипаний (ротация на 2 МБ, старый → `.log.1`) |
| `gamebar-registry-before.txt` | значения реестра Game Bar **до** отключения, для отката |
| `gamebar-removal-rollback.txt` | что за пакет Game Bar снесён и как вернуть |

## Автозапуск

Уже установлен — ярлык в папке автозагрузки:

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\win-key-watch.vbs
```

Отключить — удалить этот файл или снять галку в «Диспетчер задач → Автозагрузка».

Запустить вручную прямо сейчас:

```powershell
wscript.exe "$env:USERPROFILE\Tools\win-key-watch\start-hidden.vbs"
```

Остановить:

```powershell
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.CommandLine -like '*win-key-watch*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## Настройки

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `-RuleAHoldMs` | `1500` | сколько ждать перед срабатыванием правила A |
| `-RuleBHoldMs` | `60000` | сколько клавиша может «висеть» зажатой при активной печати, прежде чем это считается залипанием |
| `-LogPath` | `winkey.log` рядом со скриптом | куда писать |

`RuleBHoldMs` намеренно большой: держать Shift несколько секунд — нормально
(выделение текста, Shift+стрелки), а вот целую минуту подряд — уже нет. Правило A
безопасно при любом пороге, потому что расхождение там однозначное.

## Правка скриптов

PowerShell 5.1 читает `.ps1` без BOM как ANSI и ломается на кириллице. Если правишь
файл с русским текстом — сохраняй в **UTF-8 с BOM**:

```powershell
$f = "$env:USERPROFILE\Tools\win-key-watch\unstick-modifiers.ps1"
Set-Content $f -Value (Get-Content $f -Raw -Encoding UTF8) -Encoding UTF8
```

## Game Bar: что с ним сделано и как вернуть

09.09.2026 снесён насовсем — пакет `Microsoft.XboxGamingOverlay` удалён
(`Remove-AppxPackage`, без прав администратора). Дополнительно на
`HKCU\Software\Classes\ms-gamingoverlay` выставлен `NoOpenWith`, чтобы Win+G не
показывал окно «Нужно новое приложение из Microsoft Store».

Вернуть — установить «Xbox Game Bar» из Microsoft Store. Подробности и точная версия
пакета — в `gamebar-removal-rollback.txt`.

Отдельно: `Microsoft.XboxGameCallableUI` — системный (`NonRemovable`), не трогали.
`Microsoft.Edge.GameAssist` оставлен: сам по себе он не стартует, только вместе с
Game Bar.

Прежние значения реестра (до более раннего мягкого отключения) — в
`gamebar-registry-before.txt` (`<absent>` = параметра не существовало, для отката его
нужно удалить, а не выставлять в 0).
