# Windows Process Cleaner

🇷🇺 Русский · [🇬🇧 English](README.en.md)

Обслуживание Windows в одном окне: **очистка диска**, **завершение забытых процессов**,
**освобождение оперативной памяти**, **обновление установленных программ**, управление
**автозапуском**, удаление программ и чистка **Docker**.

Написана на **C# + WinForms**, собирается **встроенным в Windows компилятором
`csc.exe`** (.NET Framework 4.x). **Ничего устанавливать не нужно** — ни Node.js,
ни Rust, ни Visual Studio. Результат — один самодостаточный `.exe`, который можно просто
носить в папке.

---

## Для чего эта программа

Один инструмент вместо набора сторонних «оптимизаторов»: убрать зря висящие процессы,
освободить память, вычистить накопившийся мусор с диска и поставить вышедшие обновления —
без установки чего-либо в систему, с предпросмотром перед каждым удалением, с русским и
английским интерфейсом, работой из трея и по расписанию.

## Из чего состоит окно

Разделы — в боковой панели слева, как в Microsoft PC Manager.

| Раздел | Что делает |
|---|---|
| **Главная** | карточки памяти и диска, кнопка «Ускорить», проверка состояния системы с действиями |
| **Сканирование** | ищет заброшенные процессы и завершает их, чистит Standby Memory |
| **Dev Cleanup** | массово гасит dev-рантаймы и освобождает занятые dev-порты |
| **Очистка диска** | анализ и удаление мусора по категориям, опционально правила winapp2 |
| **Диск** | карта папок с размерами, крупные файлы, пустые папки, дубликаты; удаление только в Корзину |
| **Браузеры** | закладки по папкам, сохранённые группы вкладок, список для чтения, открытые вкладки |
| **Docker** | обзор занятого места и удаление неиспользуемого, сжатие vhdx |
| **Программы** | список установленного ПО, удаление штатным деинсталлятором |
| **Обновления** | поиск устаревших программ и их обновление через winget / Chocolatey |
| **Автозапуск** | что стартует вместе с Windows, включение и отключение |
| **Windows: лишнее** | телеметрия, реклама, Copilot, лишние приложения Store, службы и компоненты: выключить, удалить, вернуть |
| **Инструменты** | быстрые исправления Windows (DNS, сеть, SFC, DISM, гибернация…), защита, ярлыки штатных средств |
| **Настройки** | все пороги, списки и параметры |
| **История** | что и когда было очищено |

## Что программа умеет

- **Процессы.** Находит забытые/заброшенные процессы (dev-рантаймы или — в глобальном
  режиме — любые ваши) и безопасно их завершает: сначала мягко (WM_CLOSE), потом
  принудительно. Показывает по каждому: PID, PPID, путь, аптайм, CPU, RAM, окна,
  TCP-порты, дочерние процессы, владельца.
- **Оперативная память.** Очищает Standby Memory через WinAPI (`NtSetSystemInformation`),
  без сторонних exe.
- **Dev Cleanup.** Массово завершает Node/Python/Java/Vite/Webpack/npm/pnpm/yarn и
  освобождает занятые dev-порты (3000, 5173, 8080, 4200 …).
- **Очистка диска.** Анализирует и удаляет известный мусор: dev-кэши (npm/pnpm/yarn/
  pip/gradle/cargo/go/NuGet), системный мусор (temp, Корзина, Windows Update, дампы),
  кэши браузеров и приложений (Discord/Slack/Teams/Spotify), старые логи, installer-мусор
  драйверов и `Windows.old`. По желанию подключаются **правила winapp2** — открытая база
  на тысячи программ. Сначала показывает размеры, удаляет только после подтверждения. У каждой категории есть
  **состав** — список её папок с галочками, и любую папку можно исключить навсегда.
- **Диск.** Показывает, куда ушло место: дерево папок с размерами и долями, крупные файлы,
  пустые папки и дубликаты по содержимому (SHA-256). Удаляет только в Корзину.
- **Docker.** Показывает занятое место (`docker system df`) и чистит неиспользуемое:
  остановленные контейнеры, образы, тома, кэш сборки, всё сразу.
- **Программы.** Список установленного ПО с удалением через штатный деинсталлятор.
- **Обновления.** Сканирует компьютер и показывает, у каких программ вышли новые версии,
  оценивает масштаб обновления («крупное / среднее / мелкое») и устанавливает выбранные —
  силами **winget** и **Chocolatey**, по нескольку пакетов за раз.
- **Браузеры.** Показывает всё, что накопилось в профилях браузеров: дерево папок с
  закладками, сохранённые группы вкладок, список для чтения и открытые сейчас вкладки —
  с датами добавления и последнего открытия. Закладки можно чистить: удалять, переносить,
  объединять папки, искать повторы и проверять, живы ли ссылки.
- **Автозапуск.** Список всех установленных программ с тоглом «запускается при входе»:
  выключаешь — отключает, как Диспетчер задач (запись и её параметры остаются), включаешь —
  включает обратно или добавляет (реестр `Run` + папки «Автозагрузка»).
- **Автоматизация.** Таймер автоочистки процессов (каждые 1–24 ч), автозапуск с Windows
  (через Планировщик), работа в трее, история очисток, гибкие настройки.
- **Оформление.** Тёмная/светлая тема (или по системе) + тёмный заголовок окна;
  язык интерфейса RU/EN.

## Чего программа НЕ делает (границы безопасности)

- **Не ломает Windows.** Системные процессы (SYSTEM/сервисы), компоненты из `C:\Windows`,
  критичные и защищённые процессы (оболочка, облака, драйверы, мессенджеры) в глобальном
  режиме под завершение не попадают; предохранители работают «в сторону защиты».
- **Не завершает активное по ошибке.** Кандидат в скане отбирается только при совпадении
  всех критериев сразу (мёртвый родитель + простой + нет окон/портов/детей), с
  подтверждением. Исключение — кнопки Dev Cleanup: это осознанная «кувалда» по имени.
- **Не ищет дубликаты файлов по диску** и не удаляет ничего из ваших проектов, кода,
  System32 и корней дисков. Пакеты драйверов из `DriverStore` удаляются только через
  `pnputil` и только устаревшие. Чистятся только известные мусорные пути.
- **Не считает мусором сохранения и настройки.** Папки сохранений игр (`Saved Games`,
  `My Games`, `saves` / `SaveGames`, облачные сейвы Steam в `userdata`, сейвы Xbox) не
  становятся целью ни по встроенным правилам, ни по winapp2 — и не раскрываются при
  рекурсивном обходе, даже если правило указывает на папку выше них, — а корни профиля (Документы,
  Рабочий стол, AppData) не удаляются никогда. Любую папку любой категории можно исключить
  из очистки навсегда — через «Состав…».
- **Не чистит диск, не удаляет программы и не обновляет их по расписанию** — только
  вручную, с предпросмотром и подтверждением. По таймеру работает лишь очистка процессов.
- **Не правит реестр при обновлении программ.** Установку выполняет сам менеджер пакетов
  (winget / Chocolatey), приложение только показывает список и передаёт ему команду.
- **Docker: удаляет только неиспользуемое** (`prune`) — запущенные контейнеры и
  используемые образы не трогает. Kubernetes не включён.

## Установка

### Что нужно

| Требование | Пояснение |
|---|---|
| Windows 10 или 11 (x64) | Windows 8.1 тоже подойдёт |
| .NET Framework 4.x | **уже есть в Windows**, ставить не надо |
| Права администратора | нужны для очистки Standby Memory |

Ни Visual Studio, ни .NET SDK, ни Node.js, ни какие-либо пакеты **не требуются** —
программа собирается компилятором `csc.exe`, который уже лежит внутри Windows.

Отдельно (по желанию, только для соответствующих вкладок):

- **winget** — для вкладки «Обновления». В Windows 11 и свежих Windows 10 он есть
  из коробки; если нет — установите «Установщик приложений» (App Installer) из
  Microsoft Store.
- **Chocolatey** — необязательный второй источник обновлений. Если он не установлен,
  вкладка просто работает через один winget.
- **Docker Desktop** — для вкладки Docker (нужен запущенный демон).

### Шаги

1. **Получите файлы.** Либо `git clone` репозитория, либо скачайте ZIP и распакуйте
   его в любую папку, например `C:\Tools\cleaner`.

2. **Если скачивали ZIP — снимите блокировку.** Windows помечает файлы из интернета, и
   сборка может отказаться работать. Правый клик по ZIP → **Свойства** → внизу галочка
   **«Разблокировать»** → OK, и только потом распаковывайте. Уже распаковали — выполните
   в PowerShell в папке проекта:

   ```powershell
   Get-ChildItem -Recurse | Unblock-File
   ```

3. **Запустите `run.bat`** двойным кликом. При первом запуске он соберёт
   `WindowsProcessCleaner.exe` и сразу откроет его. Дальше можно запускать сам `.exe`.

   Только сборка, без запуска:

   ```
   build.bat
   ```

4. **Подтвердите запрос UAC.** Программа всегда запускается от администратора — это
   нужно для очистки Standby Memory. Запрос при каждом запуске — нормально.

Всё. Устанавливать в систему ничего не нужно: `WindowsProcessCleaner.exe` —
самодостаточный файл, его можно просто носить с собой в папке.

### Если что-то не пошло

**«Windows защитила ваш компьютер» (SmartScreen).** Файл собран у вас локально и не
подписан сертификатом, поэтому Windows его не знает. Нажмите **«Подробнее»** →
**«Выполнить в любом случае»**.

**Антивирус ругается на свежесобранный `.exe`.** Это ложное срабатывание на
неподписанный файл. Добавьте папку проекта в исключения или соберите заново.

**`[ERROR] csc.exe of .NET Framework 4.x not found`.** В системе нет .NET Framework 4.x
(бывает на сильно урезанных сборках Windows). Установите .NET Framework 4.8 с сайта
Microsoft и повторите.

**`[ERROR] Build failed`.** Чаще всего программа уже запущена и держит свой `.exe`.
Закройте её (в том числе из трея — правый клик по иконке → «Выход») и соберите снова.

**Окно не появилось после запуска.** Вероятно, приложение уже работает: оно
однооконное и просто разворачивает уже открытое окно. Посмотрите в трей у часов.

**Не собирается из папки с очень длинным путём.** Перенесите проект ближе к корню
диска, например в `C:\Tools\cleaner`.

### Как удалить

1. В настройках снимите галочку **«Запускать вместе с Windows»** — задача
   `WindowsProcessCleaner` в Планировщике задач удалится.
2. Закройте программу (трей → «Выход»).
3. Удалите папку проекта и папку настроек `%APPDATA%\WindowsProcessCleaner\`.

Ничего другого в системе программа не оставляет: в реестр она себя не прописывает
и служб не создаёт.

## Возможности

### Главная
Стартовый экран — как в Microsoft PC Manager: три карточки (оперативная память, системный
диск, состояние после последней проверки), большая кнопка **⚡ Ускорить** и таблица
проверок.

- **Ускорить** — завершает заброшенные процессы (текущие кандидаты сканирования) и
  чистит Standby Memory; результат пишется под карточками и в историю. С галочкой
  «и временные файлы» перед удалением показывает список категорий и спрашивает.
- **Умное ускорение** — галочка тут же и в настройках: когда память занята сильнее
  порога (по умолчанию 90 %), приложение само чистит Standby Memory, не чаще раза в
  15 минут, и сообщает об этом подсказкой в трее.
- **Проверить состояние** — 12 проверок за несколько секунд: память, системный диск,
  время без перезагрузки, файл гибернации, автозапуск, заброшенные процессы, объём
  временных файлов, папка «Загрузки», Защитник (включён ли, свежесть баз и последней
  проверки), последнее обновление Windows, точки восстановления, обновления программ.
  У каждой строки статус (в порядке / совет / внимание) и действие: двойной щелчок
  открывает нужную вкладку, запускает инструмент или само ускорение. Статус подсвечен
  цветом (зелёный / синий / оранжевый). Проверка запускается при первом показе «Главной»
  и повторяется сама, если прошлой больше часа.

### Сканирование
По каждому процессу собирается: имя, PID, PPID, путь, время работы, CPU %, RAM,
наличие окна, слушающие TCP-порты, наличие дочерних процессов, владелец.

### Критерии «заброшенности»
Процесс становится кандидатом на завершение, только если выполнены **все** условия:
1. родительский процесс завершён;
2. CPU ниже порога дольше заданного времени простоя;
3. нет пользовательских окон;
4. не слушает TCP-порты;
5. нет дочерних процессов;
6. не в белом списке и старше минимального времени жизни.

### Два режима поиска
- **Dev-режим** (по умолчанию) — только процессы из списка отслеживаемых
  (node, python, java, vite, webpack, npm, pnpm, yarn, bun, cargo, go, deno, ruby, php…).
- **Глобальный режим** (галочка «Все процессы (глобально)») — сканируются **все**
  процессы системы. Здесь действуют **усиленные предохранители**: завершаются только
  процессы **текущего пользователя**, лежащие **не в системных папках** Windows и
  **не в `Program Files`** (установленный софт, настраивается), простаивающие **≥ 30
  минут** (настраивается), не входящие в расширенный список защищённых (ядро Windows,
  оболочка, облака, мессенджеры, драйверы, лаунчеры, менеджеры паролей). Именно так
  отлавливаются осиротевшие группы, у которых родитель давно умер, а дети остались
  висеть и грузить проц/память, ничем не используясь.

### Кнопки очистки
- **Очистить выбранные** — завершить отмеченные в таблице.
- **Автоочистка всех неактивных** — завершить всех найденных кандидатов одним
  нажатием (с подтверждением и списком).
- **Выбрать все / Снять выбор** — управление галочками.
- **Очистить память** — только очистка Standby Memory без завершения процессов.

Само завершение: сначала мягко (WM_CLOSE), ожидание до 3 секунд, затем принудительно.

### Dev Cleanup
Массовое завершение по группам: всё Node / Python / Java / Vite / Webpack / npm /
pnpm / yarn·bun / Docker Compose / Go·Cargo·Deno. Плюс список процессов, занявших
популярные dev-порты (3000, 5173, 8080, 4200 …) с возможностью их завершить. Слушатели
видны и по IPv4, и по IPv6 (Node и Vite по умолчанию слушают `::`).

> В Dev Cleanup завершение идёт **по имени, не глядя на активность** (кроме белого
> списка) — это осознанная «кувалда».

### Очистка диска (только вручную)
Отдельная вкладка. Флоу: **Анализировать → предпросмотр с размерами → удалить
выбранное**. Автоочистки диска нет намеренно (файлы менее обратимы, чем процессы).
Чистятся только **известные мусорные пути**; карта диска, крупные файлы, пустые папки и
дубликаты живут на соседней вкладке «Диск». Категории:
- **Dev-кэши** — npm / pnpm / yarn / bun / pip / uv / poetry / gradle / cargo / go / NuGet /
  Composer / TypeScript, старые сборки браузеров Playwright (всё пересоздаётся).
- **Dev: скачанные тулчейны** — браузеры Playwright/Puppeteer/Cypress, electron-builder,
  dotslash, Expo Go, репозиторий Maven. Скачаются заново, но долго — не отмечены по умолчанию.
- **Системный мусор** — `%TEMP%`, `Windows\Temp`, temp служебных профилей, Корзина, кэш
  Windows Update, crash dumps, отчёты об ошибках, Delivery Optimization. `Prefetch` намеренно
  не трогается: это кэш запуска программ, весит мегабайты, а после удаления всё стартует
  медленнее, пока Windows не соберёт его заново.
- **Кэши Windows** — thumbcache/iconcache, кэш шрифтов, картинки уведомлений, кэш RDP —
  Windows пересобирает их сама.
- **Кэши шейдеров GPU** — DirectX (`D3DSCache`), NVIDIA/AMD/Intel и `shadercache` Steam.
  После очистки игры и Chrome/Electron компилируют шейдеры заново и первые минуты
  подтормаживают, а места это даёт мало — не отмечены по умолчанию.
- **Кэши приложений Microsoft Store** — `INetCache` / `Temp` / `TempState` каждого UWP-пакета
  и WebView-кэш нового Teams. `LocalState` и настройки приложений не трогаются.
- **Кэши браузеров** — Chrome / Edge / Brave / Yandex / Opera / Vivaldi / Firefox, только кэш
  (без паролей, куки и истории).
- **Кэши приложений** — Discord / Slack / Teams / Spotify / VS Code / JetBrains / Steam /
  Telegram (включая `media_cache`) / Figma / игровые лаунчеры, только кэш.
- **NVIDIA: кэши и старые версии** — старые версии моделей NGX (DLSS, Broadcast и т.д.).
  NGX Updater докачивает новые версии в `ProgramData\NVIDIA\NGX\models\<модель>\versions`
  и никогда не удаляет старые — за год набегают гигабайты. Плюс кэш NVIDIA App/Overlay,
  загрузчик драйверов, `C:\NVIDIA`. Самая новая версия каждой модели и сам драйвер остаются.
  База распознавания игр NVIDIA App (`NvBackend\ApplicationOntology`) не трогается: без неё
  NVIDIA App перестаёт узнавать игры, пока не скачает базу заново.
- **Старые логи** — логи CBS/DISM/установки Windows, Update Orchestrator, npm/yarn/gradle,
  Docker Desktop, OneDrive, Zoom, Chocolatey.
- **Списки недавних файлов** — «Недавние документы», списки переходов (приватность).
- **Старые версии программ** — копии предыдущих версий, которые оставляют автообновления:
  Squirrel-приложения (Postman, Figma, Discord и т.п. держат папку `app-<версия>` на каждую
  скачанную версию) и WPS Office (папка предыдущей версии рядом с текущей). Текущая версия
  определяется по номеру, у WPS — по реестру. Не отмечается по умолчанию.
- **Остатки обновлений Windows и драйверов** — `Windows.old`, `$Windows.~BT`, `$WinREAgent`,
  `$GetCurrent`, `ESD`, распакованные установщики AMD/Intel, `NVIDIA Installer2`. Остатки
  обновлений удаляются только старше 10 дней — столько их хранит сама Windows на случай отката.
- **Старые пакеты драйверов (DriverStore)** — версии, которые заменены более новыми и не
  привязаны ни к одному устройству. Список строится по `pnputil /enum-drivers`, удаление —
  `pnputil /delete-driver` без `/force`: если пакет нужен системе, pnputil откажет сам.
  Папки в `FileRepository` напрямую не удаляются никогда.
- **Хранилище компонентов Windows (WinSxS)** — устаревшие версии компонентов, оставшиеся
  после обновлений. Размер считается `DISM /AnalyzeComponentStore`, очистка —
  `DISM /StartComponentCleanup` (единственный поддерживаемый способ). После неё уже
  заменённые обновления нельзя откатить, поэтому категория не отмечается по умолчанию.

Предохранители: пропускаются занятые файлы и точки повторного разбора (junction); напрямую
никогда не трогаются `DriverStore` (только через `pnputil`), `Windows\Installer`, WinSxS,
System32, корни дисков, код и проекты. Файлы, которые изменялись в последние N минут, не
удаляются (N настраивается, по умолчанию 10). Категории с несколькими версиями одной
сущности всегда оставляют самую новую. Каждая очистка пишется в лог `clean-ГГГГ-ММ.log` —
кнопка «Лог» открывает его.

**Состав категории.** Двойной клик по категории (кнопка «Состав…» или Enter) открывает
список её папок: путь, размер, число файлов и примечание — только содержимое или папка
целиком, фильтр по возрасту, сколько папок оказались недоступны. Самое крупное сверху.
Снимите галочку с того, что удалять не нужно, — выбор запоминается в `config.json` и
действует при каждом анализе и удалении, пока вы не вернёте галочку. Отключённые папки не
входят в размер категории, а в её описании появляется пометка «отключено вами: N». Пакеты
драйверов исключаются так же, по одному; у хранилища компонентов (DISM) состава нет.
Двойной клик по строке или «Открыть папку» показывает её в проводнике.

**Правила winapp2 (необязательно).** Кнопка «Правила winapp2» скачивает
[Winapp2.ini](https://github.com/MoscaDotTo/Winapp2) — открытую базу с тысячами правил
очистки для конкретных программ, и добавляет их к встроенным категориям. Из неё берутся
**только правила удаления файлов**: разделы с предупреждениями (`Warning=`) и с
исключениями (`ExcludeKey`) пропускаются целиком, а правила для реестра игнорируются —
реестр программа не чистит вообще. Результаты из winapp2 никогда не отмечаются галочкой
автоматически.

Файл правил — это чужой текст, который приложение исполняет правами администратора, поэтому
он ограничен отдельно от встроенных правил:

- **Скачанная база лежит в защищённой папке** `C:\ProgramData\WindowsProcessCleaner\` с
  правами «администраторы и SYSTEM — полный доступ, пользователи — только чтение». В прежнем
  месте (`%APPDATA%`) файл мог переписать любой процесс, запущенный от вашего имени, — а
  чистка идёт от администратора. Старая копия при следующей загрузке удаляется. Если папку
  создать не удалось (запуск без прав администратора), используется прежнее место.
- **Правилу из файла закрыты системные пути целиком**: внутрь `C:\Windows` оно попадает
  только в заведомо мусорные подпапки (`Temp`, `Prefetch`, `Logs`, `Minidump`, `Debug`,
  `SoftwareDistribution\Download`, `System32\LogFiles`, `Downloaded Program Files`), в
  `Program Files` и в чужие профили пользователей — никогда, и корень `C:\Windows` не
  открывается даже узкой маской вида `%WinDir%|*.log`. Встроенные правила (MEMORY.DMP в
  `C:\Windows`, `IconCache.db` в `%LOCALAPPDATA%`) работают как прежде: их нельзя подменить.
- **Предохранитель сохранений и служебных баз действует на каждую папку обхода**, а не
  только на корень правила: правило с `RECURSE` над `%LocalAppData%\NVIDIA Corporation`
  не спустится в `NvBackend\ApplicationOntology`, а над профилем — в `Saved Games`.

### Диск
Отдельная вкладка: **где место и что можно убрать руками**. Выбираете диск или папку
(«Где искать»), нажимаете **Сканировать** — слева дерево папок с размером, долей от
родительской папки и числом файлов (раскрывается по мере надобности), справа список в одном
из трёх режимов:
- **Крупные файлы** — файлы не меньше порога «Файлы от N МБ» (по умолчанию 1 МБ, значение
  запоминается) в выбранной папке и её подпапках, по убыванию размера. Порог можно поднять и
  после сканирования — список сузится сразу; опустить ниже того, с которым шёл обход, —
  только пересканировав (программа подскажет).
- **Пустые папки** — только верхние пустые: если пуста `a\b\c`, показана `a`, а сколько
  вложенных пустых внутри — в строке над списком.
- **Дубликаты** — файлы не меньше того же порога с одинаковым содержимым. Сравнение идёт в три шага: размер →
  первые 64 КБ → полный SHA-256, поэтому целиком читаются только настоящие кандидаты.
  В группе первым идёт самый старый файл (обычно оригинал); кнопка **Все** отмечает в каждой
  группе все копии, кроме него.

Удаление — только **В Корзину**, одной операцией оболочки и после подтверждения; всё
восстанавливается штатно из Корзины. По умолчанию ничего не отмечено. Двойной щелчок по
папке или **Открыть папку** показывает её в Проводнике.

Что учтено:
- Внутри `Windows`, `Program Files`, `ProgramData`, `AppData\Local\Packages`, `node_modules`
  и `.git` пустые папки и дубликаты не предлагаются — там одинаковые файлы и пустые каталоги
  в порядке вещей, а удаление ломает программы.
- Точки повторного разбора (junction, symlink, папки OneDrive) не раскрываются и не
  считаются дважды; у папки в дереве видно, сколько ссылок пропущено и куда нет доступа.
  Пути длиннее 260 знаков читаются, хэшируются и переносятся в Корзину (оболочке они
  передаются короткими именами 8.3; на томе, где короткие имена отключены, такой путь
  в Корзину не попадёт — программа скажет, сколько путей осталось).
- Скрытые и системные файлы в дубликаты не попадают.
- Полосы занятости всех дисков — над деревом. Скан не отменяется при переходе на другую
  вкладку; **Стоп** прерывает его.
- Ключ `/disk [путь]` открывает вкладку и сразу сканирует путь — удобно для ярлыка или
  вызова из Проводника.

### Программы (деинсталляция)
Вкладка со списком установленных программ (имя, версия, издатель, размер). Отмечаешь
и удаляешь через приложение — запускается штатный деинсталлятор программы. Несколько
отмеченных программ удаляются по очереди: следующий деинсталлятор стартует после
завершения предыдущего (два установщика MSI одновременно не работают). Если
деинсталлятор не найден (программу удалили вместе с папкой, запись в реестре осталась),
приложение сообщает об этом и показывает путь; по окончании список перечитывается.
Записи с одинаковым именем (две версии одной программы) показываются отдельно. Если
деинсталлятор-загрузчик сразу завершается и оставляет работать дочерний процесс, программа
ждёт его потомков и исчезновения записи в реестре, прежде чем перечитать список.

### Обновления программ
Вкладка находит устаревшие программы по всему компьютеру и обновляет их. Флоу:
**Проверить обновления → отметить нужные → Обновить выбранное**.

**Откуда берутся данные.** Опрашиваются менеджеры пакетов: **winget** (официальная база
Microsoft, десятки тысяч пакетов) и, если он установлен, **Chocolatey**. Сопоставление
установленной программы с пакетом и сравнение версий делает сам менеджер — приложение не
держит собственную базу версий, которая неизбежно отставала бы от реальности.

**Колонка «Важность»** показывает масштаб скачка версии:

| Значение | Когда |
|---|---|
| **крупное** | меняется старшая часть версии (14.1.3 → 15.1.1), поведение может измениться |
| **среднее** | новые возможности, совместимость обычно сохраняется (2.5.1 → 2.7.3) |
| **мелкое** | исправления и правки сборки (3.14.2 → 3.14.7) |
| **неизвестно** | менеджер не сообщает точную установленную версию |

Крупные обновления идут первыми в списке и подсвечиваются, чтобы их не пришлось искать
прокруткой. Для версий вида `0.x` смена второй части тоже считается крупной — по правилам
semver именно там в таких проектах происходят ломающие изменения.

> ⚠️ **«Важность» — это масштаб смены версии, а не оценка безопасности.** Ни winget, ни
> Chocolatey не отдают данные о CVE и критичности, поэтому вывести настоящую «критичность»
> из них невозможно, и приложение этого не изображает. Если нужно знать, закрывает ли
> обновление уязвимость, смотрите release notes самой программы.

**Групповое обновление.** Отмеченные пакеты передаются менеджеру не по одному, а группами
(по умолчанию 5 за команду, настраивается 1..20; 1 — строго по одному). Это экономит запуск
процесса и загрузку индекса источника на каждый пакет.

Установщики при этом всё равно работают **по очереди**, и это не ограничение приложения:
Windows Installer держит машинный мьютекс `_MSIExecute`, а Chocolatey — свой глобальный
лок, поэтому два установщика, запущенных одновременно, просто завершатся ошибкой.

**Как определяется результат.** После группы приложение заново спрашивает менеджер, что
ещё осталось устаревшим, и сверяет список. Так результат по каждому пакету получается
верным независимо от языка системы — разбирать локализованный текст вывода было бы гадание.

**Прочее на вкладке:**

- **Дубли.** Один и тот же софт может быть виден и через winget, и через Chocolatey. Такие
  строки помечаются и приглушаются, а кнопка «Все» их не отмечает — обновлять одно и то же
  двумя менеджерами не нужно. Пометка ни на что не влияет, кроме подсказки: отметить строку
  вручную всё равно можно.
- **«Не предлагать»** — добавляет выделенные пакеты в список исключений (настройки),
  и они больше не появляются при проверке.
- **«Лог»** — открывает `updates-ГГГГ-ММ.log`: что, когда, с какой версии на какую и с
  каким результатом обновлялось.
- **Ничего не отмечено заранее.** Обновление — действие пользователя, поэтому по кнопке
  «Обновить выбранное» сначала показывается список того, что будет обновлено, с версиями,
  и запрашивается подтверждение.
- Пакеты, у которых менеджер не знает установленную версию, показываются по умолчанию —
  это отключается в настройках.

> Установщик может закрыть и перезапустить обновляемую программу. Сохраните работу перед
> обновлением того, что открыто.

### Браузеры

Вкладка показывает то, что копится в профилях браузеров годами и обычно нигде не видно
целиком. Ничего не устанавливается и не подключается к браузеру — всё читается прямо
из файлов профиля.

**Что находится само.** Все профили всех установленных браузеров на движке Chromium:
Chrome (включая Beta / Dev / Canary), Edge, Yandex Browser, Brave, Vivaldi, Opera и
Opera GX, Chromium. У каждого профиля показывается его настоящее имя, а не имя папки.
Firefox не поддерживается: его закладки и сессии лежат в SQLite (`places.sqlite`), а вкладка
читает форматы Chromium; кэш Firefox при этом чистит «Очистка диска».

**Что показывается по каждому профилю**

| Раздел | Что внутри | Откуда берётся |
|---|---|---|
| **Закладки** | дерево папок; у каждой — сколько ссылок прямо в ней и сколько всего с подпапками | файл `Bookmarks` |
| **Дубликаты URL** | один и тот же адрес, сохранённый в разных папках | вычисляется |
| **Группы вкладок** | сохранённые группы: имя, цвет, состав, когда менялась последний раз | база синхронизации |
| **Список для чтения** | отложенные страницы, прочитанные и нет | база синхронизации |
| **Открытые вкладки** | текущий сеанс: окна, вкладки и их группы | файлы `Sessions` |

Для каждой строки видно название, адрес, где она лежит, когда добавлена и когда её
последний раз открывали — по этому и понятно, что можно выкидывать.

**Что можно делать**

- **Удалить выбранное** — отмеченные ссылки и папки целиком.
- **Переместить…** — перенести отмеченное в другую папку. Галочка «Объединять» в
  диалоге переносит *содержимое* отмеченных папок, а сами папки удаляет — так две
  папки про одно и то же схлопываются в одну.
- **Дубликаты** — показывает все повторяющиеся адреса и заранее отмечает лишние копии,
  оставляя нетронутой ту, которую открывали позже всех.
- **Проверить ссылки** — обходит адреса из текущего списка и пишет, что ответил сайт
  (`OK`, `404`, `нет домена`, `таймаут`…). Работа сетевая и небыстрая, поэтому только
  по кнопке и с кнопкой «Стоп». `403` чаще всего означает не мёртвую ссылку, а защиту
  от ботов: сайт отвечает так на запрос не из браузера. Проверяйте такие адреса руками,
  прежде чем удалять.
- Правая кнопка мыши: открыть в браузере, копировать адрес, отметить всё, снять
  отметки. В дереве — «Удалить пустые папки», «Удалить эту папку» и «Сохранить группу
  в закладки».

**Что менять нельзя и почему**

Группы вкладок и список для чтения живут в базе синхронизации браузера. Удалить их
оттуда файлом невозможно: браузер держит своё состояние в памяти и восстановит запись
с сервера. Поэтому эти разделы — только для просмотра. Если группа не нужна, но ссылки
из неё жалко, есть пункт **«Сохранить группу в закладки»**: он создаёт папку в «Других
закладках» со всеми вкладками группы, после чего саму группу можно спокойно удалить
в браузере.

**Как программа бережёт закладки**

- Правка возможна **только при полностью закрытом браузере**. Запущенный браузер держит
  закладки в памяти и при выходе перезапишет файл — правка просто потерялась бы.
- **Перед каждой записью** файл копируется в `%APPDATA%\WindowsProcessCleanerrowser-backups\`
  с отметкой времени. Копии не удаляются автоматически.
- У файла закладок есть контрольная сумма, которую считает сам браузер. Программа
  сначала пересчитывает её для **нетронутого** файла и сверяет с записанной. Не совпало —
  значит у этой сборки браузера свой алгоритм, и профиль переводится в режим «только
  просмотр»: лучше ничего не менять, чем отдать браузеру файл, который он сочтёт битым.
- Запись идёт через временный файл, а не поверх исходного.

### Автозапуск
Вкладка со списком всех установленных программ и чекбоксом-тоглом. Галочка стоит —
программа запускается при входе в Windows. Снять галочку — отключить запись так, как это
делает Диспетчер задач: флаг в `...\Explorer\StartupApproved`, а само значение `Run` с его
параметрами командной строки или ярлык остаются на месте, и галочку можно вернуть.
Поставить — включить существующую запись, а если записи нет — добавить её в
пользовательский `HKCU\...\Run`. Читает реестр (`HKCU\...\Run`, `HKLM\...\Run`, 32-битный
`Run`) и папки «Автозагрузка» (пользователь + общая); записи, отключённые в Диспетчере
задач или в «Параметрах → Автозагрузка», показаны без галочки с пометкой «отключено».
Оранжевым помечаются записи автозапуска, которых нет в списке установленных программ
(скрипты, ярлыки) — их тоже можно включать и отключать. Ничего не удаляется: программа не
убирает значения из реестра и не стирает ярлыки.

Windows и модули PowerToys (читаются из его `settings.json`). Слева дерево с галочками,
справа для каждого пункта: что это, зачем выключать, чем рискуете, рекомендация и что
именно будет сделано (какие значения реестра, службы, задачи планировщика, пакеты).

Галочкой по умолчанию отмечен только универсальный мусор: телеметрия, реклама и подсказки,
Bing в «Пуске», виджеты, мёртвые и рекламные приложения Store, ненужные службы и компоненты
(PowerShell 2.0, SMB 1.0, XPS…). Всё спорное — Copilot, Recall, Xbox Game Bar, OneDrive,
Teams, Phone Link, индексирование поиска — в списке без галочки и с предупреждением ⚠.

Кнопки: **«Проверить состояние»** (читает реестр, службы, задачи планировщика, пакеты Store
и — только с правами администратора — компоненты через DISM), **«Выключить отмеченное»**,
**«Удалить отмеченное»**, **«Вернуть отмеченное»**, «Отметить рекомендуемое», «Снять все».
Перед первым действием над пунктом его прежнее состояние сохраняется в
`debloat-snapshot.json`; «Вернуть» откатывает по снимку. Для приложений Store «Выключить» —
снять у текущего пользователя (обратимо: «Вернуть» регистрирует пакет заново из образа
Windows), «Удалить» — снять у всех пользователей и убрать из образа (вернуть можно только
через Microsoft Store, программа открывает в нём поиск). Без прав администратора
выполняется только то, что относится к текущему пользователю (HKCU, приложения Store,
PowerToys); остальное помечается «нужны права администратора», а при попытке выполнить
попадает в журнал как ошибка.

### Docker
Вкладка для очистки Docker (нужен Docker CLI + запущенный демон). Кнопки: обзор
занятого места (`docker system df`), удалить остановленные контейнеры, неиспользуемые
образы, неиспользуемые тома, очистить кэш сборки, полная очистка всего неиспользуемого.
Удаляется только **неиспользуемое** (`prune`) — запущенные контейнеры и используемые
образы не трогаются.

> ⚠️ **Важно про место на диске.** Docker Desktop хранит всё в одном растущем
> виртуальном диске WSL2 (`docker_data.vhdx`). `prune` освобождает место **внутри**
> этого диска, но сам файл на Windows **не уменьшается**. Чтобы реально вернуть место
> на диске Windows — кнопка **«Сжать диск Docker»**: она останавливает Docker
> (`wsl --shutdown`) и сжимает vhdx через `diskpart compact vdisk`, показывая размер
> до/после. Все запущенные контейнеры при этом завершаются.

Что удалить перед сжатием, задаёт список рядом с кнопкой: «ничего», «безопасное»
(остановленные контейнеры, образы без тега, кэш сборки — по умолчанию), «+ все
неиспользуемые образы» или «всё неиспользуемое, включая тома». Последний вариант стирает
данные баз и других контейнеров в томах, о чём программа предупреждает отдельно.

Kubernetes не включён (его очистка бьёт по живому кластеру).

### Инструменты
Штатные средства Windows одной кнопкой, с журналом вывода внизу страницы и кнопкой
«Остановить» для долгих операций.

- **Быстрые исправления:** сброс кэша DNS, сброс сети (Winsock, TCP/IP), перезапуск
  Проводника, пересборка кэша значков и кэша шрифтов, `sfc /scannow`, `DISM
  /RestoreHealth`, проверка системного диска (chkdsk при следующей загрузке), сброс
  компонентов Windows Update, создание точки восстановления, включение/отключение
  гибернации (кнопка показывает размер hiberfil.sys), сброс очереди печати, сброс кэша
  Microsoft Store, очистка буфера обмена.
- **Защита:** быстрая проверка Защитником, обновление антивирусных баз, проверка
  обновлений Windows.
- **Инструменты Windows:** 28 ярлыков — Безопасность Windows, Очистка диска, Параметры
  хранилища, Диспетчер задач, Монитор ресурсов, Диспетчер устройств, Службы, Просмотр
  событий, Монитор стабильности, Центр обновления, Программы и компоненты, Компоненты
  Windows, Восстановление системы, Защита системы, автозагрузка, сетевые подключения,
  электропитание, переменные среды, msconfig, Управление дисками, msinfo32, dxdiag,
  проверка памяти, regedit, Панель управления, Параметры, Терминал.
- **Поиск** — поле над кнопками фильтрует их по названию и описанию (Esc очищает);
  секции без совпадений скрываются.

Всё, что меняет систему, сначала спрашивает; то, что требует прав администратора,
предлагает перезапуститься от администратора. Подпись внизу боковой панели всегда
показывает, есть ли эти права.

### Долгие операции: прогресс и остановка
Ни одна кнопка не «залипает» молча. Любая работа дольше секунды показывает в подписи
страницы одну и ту же строку: **что делается сейчас · сколько уже идёт (мм:сс) · живая
подробность** — имя категории, папки, пакета или команды, которая выполняется прямо
сейчас. Подпись обновляется два раза в секунду, поэтому видно и то, что процесс идёт, и
то, на чём именно он застрял.

- **Кнопки страницы гаснут на время работы** — повторный клик не запустит вторую копию
  той же операции.
- **«Остановить» останавливает по-настоящему** — включая создание точки восстановления и
  прочие инструменты, которые раньше приходилось досиживать до конца. После нажатия
  подпись честно показывает «Останавливаю…», пока текущий шаг доходит до безопасной
  границы: наполовину удалённых или наполовину применённых изменений не остаётся.
  Единственное исключение — уже начатое сжатие диска Docker: его прервать нельзя, иначе
  виртуальный диск останется подключённым, и программа предупреждает об этом при нажатии.
- **Внешние программы не могут подвесить окно.** `DISM`, `winget`, `choco`, `pnputil`,
  `sfc`, `docker` запускаются с закрытым стандартным вводом (иначе вопрос вида
  «перезагрузить сейчас? (Y/N)» ждал бы ответа, которого графическому приложению негде
  взять), их вывод читается на лету, у каждой команды свой предел ожидания, а результат
  определяется по разобранному отчёту, а не только по коду возврата.
- **Если сделать ничего нельзя** — нет прав администратора, не установлен winget, диск
  занят — программа пишет об этом в подпись или в журнал сразу, а не оставляет кнопку
  без реакции.

### Запомненный выбор
Отмеченное вами не сбрасывается. Раньше почти любой список, обновившись, возвращал
галочки к умолчанию — и расставленное руками пропадало; теперь выбор помнит одно общее
хранилище на всё окно.

- **Переживает перезапуск программы** (лежит в `config.json`): флажок «и временные файлы»
  на «Главной», отмеченные категории на вкладке «Очистка», пункты на вкладке «Windows:
  лишнее», выбранные пакеты на вкладке «Обновления», выбор в списке «Где искать» на
  вкладке «Диск».
- **Переживает обновление списка в пределах сеанса**: отмеченные программы на вкладке
  «Программы», порты в Dev Cleanup, процессы после повторного сканирования, строки на
  вкладках «Диск» и «Браузеры». После перезапуска эти списки начинаются с чистого листа
  намеренно: их содержимое ищется заново каждый раз, и вернуть галочку «удалить» на
  другой файл, случайно оказавшийся по тому же пути, было бы опаснее, чем поставить её
  заново.
- **Умолчания остались прежними** и действуют, только пока вы сами ничего не решили: на
  вкладке «Очистка» изначально отмечены рекомендованные непустые категории, на вкладке
  «Обновления» — ничего. Как только вы переставили галочку, программа держится вашего
  выбора, и повторный анализ его больше не сбивает.
- **Не запоминаются галочки на вкладке «Автозапуск»** — там галочка не выбор, а текущее
  состояние записи в Windows; «вспомнить» его значило бы соврать про систему.

Кнопки «Рекомендуемые», «Все» и «Ничего» работают как раньше — они задают выбор целиком,
и он тоже запоминается.

### Язык интерфейса
Русский / English — переключается в настройках (применяется после перезапуска).
Документация тоже двуязычная: [README.md](README.md) / [README.en.md](README.en.md).

### Таймер автоочистки
Задаёшь число часов (1..24). Каждые N часов приложение само сканирует **процессы**
(в выбранном режиме), завершает кандидатов, чистит память и пишет в историю. Очистка
диска и деинсталляция по таймеру **не выполняются** — только вручную.

### Системный трей
Иконка в трее меняет цвет: зелёная — чисто, оранжевая — есть кандидаты. Двойной
клик — открыть окно. Правый клик — меню: Сканировать, Очистить, Очистить Standby
Memory, ⚡ Ускорить, вкл/выкл автоочистку, перезапуск от администратора, выход. Закрытие окна
сворачивает приложение в трей (продолжает работать в фоне).
Если в этот момент идёт необратимая операция (удаление файлов, перенос в Корзину,
установка обновлений, prune или сжатие диска Docker), подсказка в трее назовёт её, а
«Выход» и «Перезапустить от администратора» сначала переспросят: прерванное сжатие
оставило бы Docker остановленным, прерванная установка — пакет наполовину.

### Автозапуск с Windows
Галочка в настройках. Реализован через **Планировщик задач** с наивысшими правами
(`schtasks /RL HIGHEST`), поэтому при входе в систему UAC не появляется.

### Темы оформления
Светлая / тёмная / **по системе** (по умолчанию — следует за темой Windows, в том числе
при переключении тёмной/светлой на ходу, без перезапуска). Переключается в настройках,
применяется сразу, включая заголовок окна и уже заполненные списки (строки не остаются в
цветах прежней темы). Списки, деревья, поля ввода и выпадающие списки обведены мягкой скруглённой рамкой цветом темы, а не резкой системной линией; кнопки рисуются
со сглаженными скруглёнными углами. Раскрытый выпадающий список тоже в цветах темы: просторные
строки, выделение как в списках, в тёмной теме — тёмное окно списка. Многострочные списки на
странице настроек растягиваются на свободную высоту окна.

### Настройки (сохраняются)

- **Критерии заброшенности** — порог CPU, время простоя, минимальное время жизни,
  простой для глобального режима.
- **Автоматизация** — период автоочистки процессов (1..24 ч), включение автоочистки,
  «глобально: не трогать Program Files», автозапуск с Windows, старт свёрнутым в трей.
- **Производительность** — фоновый мониторинг CPU и его период (5..300 с, по умолчанию
  15), сброс рабочих наборов всех процессов (по умолчанию выключен — он замедляет систему),
  умное ускорение и его порог занятости RAM (50..99 %, по умолчанию 90).
  Простой процессов измеряется только тиками мониторинга: если он выключен, кандидатов на
  завершение не будет — сводка сканирования прямо об этом предупредит.
- **Очистка диска** — «не удалять файлы свежее N минут», ведение лога очистки, список
  путей, которые не чистить (путь можно записать и коротким 8.3-именем или через junction —
  сравнивается настоящий путь на диске).
- **Обновления программ** — показывать пакеты с неизвестной установленной версией,
  опрашивать Chocolatey, сколько пакетов передавать менеджеру за одну команду (1..20),
  список пакетов, которые не предлагать к обновлению.
- **Списки** — отслеживаемые процессы, белый список, dev-порты.
- **Оформление** — тема и язык интерфейса.

### История
После каждой очистки сохраняются дата/время, количество завершённых процессов,
объём освобождённой памяти и список процессов.

## Безопасно ли это?

**Режим сканирования/автоочистки — да.** Кандидат отбирается только при совпадении
**всех** критериев сразу, поэтому активный процесс (с окном, слушающий порт, грузящий
CPU или с живым родителем) под удар не попадёт. В глобальном режиме дополнительно
защищены системные процессы и процессы других пользователей. Перед завершением
всегда запрашивается подтверждение.

**Dev Cleanup — нет**, это намеренно «кувалда»: кнопки бьют по имени всё подряд
(кроме белого списка). Используй осознанно.

## Где лежат данные

Всё в одной папке — `%APPDATA%\WindowsProcessCleaner\`. Кнопка «Папка данных» в
настройках открывает её.

| Файл | Что это |
|---|---|
| `config.json` | все настройки, включая исключённые папки категорий. Пишется через временный файл, чтобы сбой не оставил пустой конфиг; повреждённая копия сохраняется как `config.json.corrupt` |
| `history.json` | история очисток процессов |
| `debloat-snapshot.json` | прежние состояния пунктов «Windows: лишнее», по которым работает «Вернуть» |
| `clean-ГГГГ-ММ.log` | лог очистки диска (что удалено и сколько освобождено) |
| `updates-ГГГГ-ММ.log` | лог обновлений программ |
| `winapp2.ini` | скачанная база правил winapp2, если вы её загружали. С этой версии живёт не здесь, а в `C:\ProgramData\WindowsProcessCleaner\` — туда не пишет процесс без прав администратора; старая копия удаляется при следующей загрузке |
| `config.json` → `UiChecks` | запомненный выбор: что вы отметили на вкладках «Очистка», «Windows: лишнее», «Обновления», «Главная», и что выбрали в «Где искать» |
| `browser-backups\` | копии файлов закладок, снятые перед каждой правкой |
| `crash.log` | стек последней необработанной ошибки, если программа упала (показывается одно сообщение; файл можно приложить к отчёту) |

Приложение всегда запускается от администратора. Это нужно для очистки Standby

## Технические детали

- **WinAPI:** `CreateToolhelp32Snapshot`, `EnumWindows`, `GetExtendedTcpTable`,
  `OpenProcessToken`/`GetTokenInformation` (владелец процесса),
  `SendMessageTimeout(WM_CLOSE)`, `TerminateProcess` (через `Process.Kill`),
  `NtSetSystemInformation` (Standby Memory), `GlobalMemoryStatusEx`,
  `DwmSetWindowAttribute` (тёмный заголовок), `FindFirstFileExW` (обход диска с длинными
  путями `\\?\`), `SHFileOperationW` (удаление в Корзину), `SetWindowTheme` (тёмные
  полосы прокрутки).
- **Обновления программ:** вызываются `winget.exe` и `choco.exe`. Вывод `winget upgrade`
  не имеет машинно-читаемого формата (только таблица), поэтому таблица разбирается по
  позициям начала колонок из строки заголовка и по их **порядку**, а не по названиям —
  так разбор работает и на локализованном winget. Позиции считаются в ячейках терминала,
  а не в символах: иероглифы, хангыль и полноширинные символы занимают две ячейки, и строка
  с таким именем короче заголовка. Вторая таблица winget («требуется явное указание для
  обновления») разбирается по собственному заголовку.
- **Деинсталляция:** строка `UninstallString` из реестра делится на exe и аргументы самим
  приложением и запускается через `ShellExecute`, а не через `cmd /c`: cmd снимает кавычки
  с пути, где есть `&`, не запускает путь с пробелами без кавычек (Android Studio, Steam,
  InstallShield) и ломается на командах с четырьмя кавычками (NVIDIA через `RunDll32`,
  Docker Desktop). `MsiExec /I{GUID}` — это диалог восстановления, поэтому для MSI-пакетов
  вызывается `/X{GUID}` — то же, что делает «Программы и компоненты».
- **Single-instance** — именованный `Mutex` (`Local\WindowsProcessCleaner.singleinstance`).
  Локальный TCP-порт **49876** используется только для того, чтобы попросить уже
  запущенный экземпляр показать окно; если порт занят, приложение всё равно запустится
  нормально.
- **Мониторинг** процессов идёт в фоновом потоке (не в UI), период настраивается
  (5..300 с, по умолчанию 15). Данные о процессах берутся напрямую через
  `OpenProcess` + `GetProcessTimes`/`GetProcessMemoryInfo`, а не через
  `Process.GetProcessById` — последний делает полный снимок системы на каждый вызов, и на
  600+ процессах один проход занимал десятки секунд.
- Поэтому «5 минут простоя» отсчитываются с момента, как приложение начало наблюдать за
  процессом, а не с его запуска.
- **Ключи командной строки:** `/tray` — стартовать свёрнутым, `/auto` — выполнить
  автоочистку процессов и выйти, `/analyze` — посчитать мусор на диске без удаления
  (строка `TOTAL` — без двойного счёта вложенных целей, `sum=` — простая сумма категорий),
  `/disk [путь]` — открыть вкладку «Диск» и сразу просканировать путь.
- **Масштаб экрана (DPI):** окно масштабируется под 125/150 % (`AutoScaleMode.Dpi`),
  панели кнопок переносят кнопки на следующую строку, колонки настроек считаются от ширины
  подписей, а минимальный размер окна не превышает рабочую область экрана.
- **Падения:** необработанное исключение (в UI-потоке и в фоновых) пишется в `crash.log`
  в папке данных, после чего показывается одно сообщение вместо тихого закрытия.

## Файлы проекта

| Файл | Назначение |
|------|-----------|

| `icon.ico` | иконка приложения (встраивается в exe) |
| `build.bat` | сборка всех `src\*.cs` через встроенный csc.exe |
| `run.bat` | собрать при необходимости и запустить |
| `README.md` / `README.en.md` | документация (рус / англ) |
