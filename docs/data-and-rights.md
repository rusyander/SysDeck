# Данные и права администратора

Где программа хранит настройки, историю и журналы, каким операциям нужны права администратора и как именно они запрашиваются.

[← Обзор](../README.md) · [Все разделы руководства](README.md) · [🇬🇧 English](data-and-rights.en.md)

## Где лежат данные

Всё в одной папке — `%APPDATA%\SysDeck\`. Кнопка «Папка данных» в
настройках открывает её.

| Файл | Что это |
|---|---|
| `config.json` | все настройки, включая исключённые папки категорий. Пишется через временный файл, чтобы сбой не оставил пустой конфиг; повреждённая копия сохраняется как `config.json.corrupt` |
| `history.json` | история очисток процессов |
| `rebrand.log` | что перенесено со старого имени программы (Windows Process Cleaner) при первом запуске SysDeck |
| `debloat-snapshot.json` | прежние состояния пунктов «Windows: лишнее», по которым работает «Вернуть» |
| `clean-ГГГГ-ММ.log` | лог очистки диска (что удалено и сколько освобождено) |
| `updates-ГГГГ-ММ.log` | лог обновлений программ |
| `winapp2.ini` | скачанная база правил winapp2, если вы её загружали. С этой версии живёт не здесь, а в `C:\ProgramData\SysDeck\` — туда не пишет процесс без прав администратора; старая копия удаляется при следующей загрузке |
| `config.json` → `UiChecks` | запомненный выбор: что вы отметили на вкладках «Очистка», «Windows: лишнее», «Обновления», «Главная», и что выбрали в «Где искать» |
| `browser-backups\` | копии файлов закладок, снятые перед каждой правкой |
| `foldersize\` | фоновый режим «Размеры папок»: `settings.json` (его настройки), `sizes.json` (запомненные размеры), `status.json` (pid и права работающего процесса — по нему вкладка показывает состояние), свой `crash.log` |
| `capture\` | «Захват»: `settings.json` (его настройки и сочетания), `status.json` (pid, права и состояние сочетаний работающего фонового процесса), свой `crash.log`. Сами снимки лежат не здесь, а в выбранной папке, по умолчанию `Изображения\Screenshots` |
| `downloads\` | фоновый процесс загрузок: `settings.json` (его настройки), `index.json` (порядок очереди), `items\<id>.json` с копией `.bak` (по файлу на загрузку: адрес, имя, сегменты и сколько байт каждого уже сброшено на диск, журнал), `engine.log`. Cookies из браузера сюда не пишутся никогда — они живут только в памяти процесса. Сами файлы качаются в выбранную папку, до завершения — с окончанием `.wpcpart`. Связь с браузерами: `nmh\` (манифесты native messaging), `extension\` (распакованное расширение), `bridge-<браузер>.json` (когда расширение подключалось и его версия). Видео: `tools\` (`yt-dlp.exe`, `deno.exe` и `tools.json` с их контрольными суммами — только если вы их ставили), а куски недокачанного видео — рядом с будущим файлом, в папке с окончанием `.wpcmedia` |
| `crash.log` | стек последней необработанной ошибки, если программа упала (показывается одно сообщение; файл можно приложить к отчёту) |

## Права администратора

**Окно запускается с обычными правами пользователя.** Права поднимаются под конкретную
операцию: программа запускает саму себя вторым процессом, тот делает одну работу,
пишет результат в файл и завершается. Одна операция — одно окно UAC, и по подписи внизу
видно, ради чего его показали.

Прав требуют: очистка системных папок (`C:\Windows`, `ProgramData`, остатки обновлений
в корне диска), удаление драйверов из DriverStore и компонентов через DISM, очистка
Standby Memory, инструменты восстановления (SFC, DISM, chkdsk, сброс Центра обновления),
точка восстановления, изменение состава Windows, задача автозапуска и правило брандмауэра для входящих
соединений торрентов.

Прав НЕ требуют и никогда не спрашивают: всё внутри вашего профиля — кэши браузеров и
приложений, папки разработчика, Корзина, завершение своих процессов, чтение списков.

Очистка делится не по категориям целиком, а по отдельным папкам: если в категории
«Кэш приложений» полторы сотни папок внутри профиля и пять снаружи, первые чистятся
сразу и молча, а UAC спрашивают только ради этих пяти. Отказ от прав не отменяет
остальную работу — она уже сделана, а пропущенное перечислено в журнале поимённо.

Фоновая работа не показывает UAC никогда: умное ускорение по порогу памяти и
автоочистка по расписанию молча пропускают то, на что не хватает прав, и пишут об этом
в журнал. Автозапуск при входе в систему остаётся задачей Планировщика с наивысшими
правами, поэтому у автоматически открытого окна права уже есть и помощник ему не нужен.

Быстрый режим «Размеров папок» спрашивает UAC один раз — чтобы создать задачу Планировщика
`SysDeck FolderSize` с наивысшими правами. Запускает её уже сама программа,
без прав и без UAC: и при входе в Windows, и при перезапуске из трея. Удаление этой задачи
тоже требует прав.

Фоновый процесс «Захвата» прав администратора не получает никогда. Если окно запущено с
правами, оно поручает запуск Проводнику, и процесс стартует с обычным токеном пользователя.
Автозапуск — значение в `HKCU\...\Run`, без Планировщика и без UAC.

Фоновый процесс загрузок (`--downloads`) тоже работает только с обычными правами: скачанные
файлы не должны принадлежать администратору. Из окна с правами он запускается через Проводник.
Значение `SysDeck.Downloads` в `HKCU\...\Run` появляется, только пока в очереди
есть незавершённые загрузки и включено «продолжать после входа», и удаляется, когда очередь
пуста. Команды процесс принимает по именованному каналу, открытому только текущему
пользователю, и лишь от процесса того же exe; других программ он не слушает. У копии программы
с другой папкой данных (портативной или с `SYSDECK_DATA_DIR`) и канал, и значение автозапуска свои —
с суффиксом, вычисленным из пути этой папки. Пока процесс не запущен, вкладка «Загрузки» только
читает его файлы; единственное, что она пишет сама, — `settings.json` при смене настроек и вслед за ним значение автозапуска.

Связь с браузерами — три ключа в `HKCU`, без прав администратора:
`Software\Google\Chrome\NativeMessagingHosts\org.wpc.downloads` (его читают и другие браузеры на Chromium),
`Software\Microsoft\Edge\NativeMessagingHosts\org.wpc.downloads` и `Software\Mozilla\NativeMessagingHosts\org.wpc.downloads`.
Каждый ведёт к манифесту в `downloads\nmh\`. По ним браузер сам запускает `SysDeck.exe` с правами
пользователя, от которого запущен браузер. Такой процесс разговаривает только с расширением, чей идентификатор
вписан в программу, и передаёт загрузки фоновому процессу по тому же каналу. Ключи пишет только копия со
стандартной папкой данных; флажок «Связь с браузерами» и деинсталлятор их удаляют. Деинсталлятор убирает и значение
`SysDeck.Downloads` из `HKCU\...\Run`, если оно запускает удаляемую копию.

Видео: `yt-dlp` и `Deno` — **чужие программы** с открытым исходным кодом, они не входят в состав этой программы и не
скачиваются сами. Их ставит только кнопка **«Установить yt-dlp…»** в настройках загрузок, и только из официальных
выпусков на GitHub (`yt-dlp/yt-dlp` и `denoland/deno`). Перед первым запуском сверяется контрольная сумма: для yt-dlp
— с опубликованным файлом `SHA2-256SUMS` того же выпуска; не совпала — файл не запускается и прежняя версия остаётся
на месте. Записанные суммы лежат в `downloads\tools\tools.json`, и файл, изменённый после установки, программа
запускать откажется. Прав администратора установка не требует: всё пишется в папку данных пользователя. Обновление
тоже только по кнопке — флажок «Держать yt-dlp свежим» лишь проверяет наличие новой версии, не чаще раза в сутки.

Торренты. Без правила брандмауэра фоновый процесс не открывает порт для входящих, поэтому окно Windows «Разрешить
доступ» не появляется само. Правило `SysDeck (BitTorrent)` добавляет помощник с правами, и только
по кнопке **Разрешить входящие…**. Правило пропускает входящие только этой программе. **Закрыть входящие** его не
удаляет: процесс просто перестаёт слушать порт. Открытие `.torrent` и magnet-ссылок программой — ключи в
`HKCU\Software`, без прав администратора: `Classes\SysDeck.Torrent`, `Classes\SysDeck.Magnet`,
`Classes\.torrent`, `Classes\magnet`, `SysDeck\Capabilities` и значение в `RegisteredApplications`.
Прежний обработчик запоминается в `SysDeck\Associations` и возвращается при выключении. Выбор
приложения, уже сделанный в Windows, программа не перезаписывает.

Скрипты. Страница [«Скрипты»](scripts.md) сама создаёт пользовательские задачи Планировщика, без прав и без UAC. Права
администратора нужны только ремонту звука и отключению MPO: помощник с правами копирует их скрипты в
`%ProgramData%\SysDeck\toolkit` (писать туда могут только администраторы и SYSTEM), регистрирует задачи от имени SYSTEM и
пишет значение `OverlayTestMode` в HKLM. Одно нажатие — одно окно UAC, даже если отмечены оба пункта. Вне папки данных
страница пишет только то, о чём её попросили: папки скриптов (`%USERPROFILE%\.claude\tools\`, `%USERPROFILE%\Tools\`),
ключи `.wslconfig` (копия `.wslconfig.sysdeck.bak`) и свой хук в `settings.json` Claude Code (копия `settings.json.bak`).
